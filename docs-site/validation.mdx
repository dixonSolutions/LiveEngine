## 0.4.0

Observed on 2026-11-09, with Chromium 1194 (1248 aborts on text inputs on the test machine):

- `npm run test:e2e` passed 24 of 24 scenarios, three runs in a row, from an upstream clone. The eight new ones sign in through the real front screen and admin console: wrong passwords, roles, peer-to-peer between signed-in users, kick, disable, a password change across tabs, an admin reset mid-match, an external password hub through a central, and ten signed-in users at once.
- Open hubs stay open when their service has accounts, and pass the same suite.
- `cargo test --locked` 187 tests, `npm test` 99, integration 22, the Gogh Strike game's own 178 tests and build, eight repeated Rust runs, the container test, type and docs checks.

Added after the first 0.4.0 validation, observed on 2026-11-09:

- `npm run test:e2e` now has 27 results (the seat check plus scenarios 1 to 26) and passed 27 of 27 three runs in a row with Chromium 1194. Chromium is chosen by trying it: 1248 and 1243 crash on a page with a text input on the test machine and are skipped with the reason printed.
- **TURN.** Scenario 24 ran a real coturn 4.6.3 in a podman container on loopback (1 GB memory and swap cap) with `LIVEENGINE_TURN_SECRET`, and two browsers forced to `iceTransportPolicy: 'relay'`. `getStats()` showed a `relay` candidate on both sides of the selected pair (UDP, through the coturn address), every gathered candidate was a relay, and ten frames crossed the data channel. coturn refused (401) a credential whose timestamp had passed and one that lapsed five seconds after it was made, and refused one signed with another secret. This is one machine and loopback; it is not NAT traversal across real networks.
- **No GPU.** Scenario 25 ran two `LiveClient`s on a plain page in a Chromium with the GPU disabled (Chromium reports canvas and compositing as software only, WebGL on SwiftShader). They paired peer to peer and exchanged ten frames over a direct data channel. The full game is a different matter: on the same software rendering it ran at about 11 to 12 frames a second, took about three minutes to start its simulation, and in the two runs where it started, its two players were still on the hub relay five seconds after play began; in the third the simulation had not started after two minutes. Use a GPU for the game itself; LiveEngine does not need one.
- **Twenty signed-in users.** Scenario 26 put twenty users through the front screen, each under their own name, into four rooms of five, with 80 pairwise frames over direct data channels and no one left waiting.
- **Memory.** The suite's peak, measured as the memory cap scope's `memory.peak`, was 10.3 to 10.6 GB for the 24 earlier results, before scenarios cleaned up after themselves. It is now 7.9 to 8.2 GB for all 27, including twenty game pages at once (sampled every three seconds, scenarios 1 to 25 stayed under about 4 GB).
- **A pairing bug found and fixed.** A peer waiting for a partner slept until its wait ran out if a room with space opened after it last looked; in the 10-user scenario one user was left searching. Every waiting peer now watches the queue and joins such a room. A new test (`a_waiting_peer_joins_a_room_that_opens_after_it_started_waiting`) failed before the fix and passes after it.

Not verified for 0.4.0: two physical devices, NAT traversal and TURN across real networks, machines with a different GPU or none for the full game, and password hubs at more than twenty simultaneous users.

## 0.3.0

Observed on 2026-11-07:

- `cargo test --locked`, `npm test` and the release packaging ran on Linux x64 and arm64, macOS x64 and arm64, and Windows x64 through the release workflow.
- `npm run test:e2e` passed 16 of 16 scenarios, three runs in a row, from an upstream clone: real hub processes, the real bridge and real Chromium. It covers WebRTC data channels, forced relay fallback, peer-hub, hub-hub across two services, reconnect, a page reload keeping its seat, seat impersonation refused, the live hub list, schema rejection, room capacity, and four simultaneous users through the front screen. A separate run put 14 real browsers in one room, with 182 pairwise frames over direct data channels.
- One scenario ran over a LAN address on a single machine. `scripts/test-containers.sh` passed on Podman.

Not verified for 0.3.0:

- Two physical devices on a real network, NAT traversal and TURN.
- Machines without a GPU, where WebRTC timed out under software rendering.
- `npm run test:e2e` needs more than 8 GB of memory at its peak; a 10 GB cap killed one run.

Validation performed on **2026-11-04**. This is a record of observed checks, not a guarantee for other environments. Registry publication and trust configuration are separate account operations.

## Observed checks

### Rust core and Node regression

- The existing Node engine and math-game regression suites pass.
- Core tests cover FIFO ordering, rule coercion, missing scopes, invalid generators, and membership invariants.

### Hub behavior

- Authentication.
- Custom embedded handler calls.
- Scope validation.
- Pre-mutation event budgets.
- Remote credentials and redaction.
- Live registry import.
- TTL behavior.
- Peer request limits.

### OCI container integration

- Separate central and remote containers with independent tokens successfully handshake, forward player matchmaking, and import a live registry.
- Unauthenticated access is denied.
- Executed locally with Podman using the standard Dockerfile; Docker execution is also configured in CI.

### Native ping and user hub

- `/v1/ping` is unauthenticated and reports native processing time.
- Rust `ping_hub`, the `liveengine-hub ping` command, and the Node `HubClient.ping()` sampler all passed against a live hub.
- The dependency-free user hub interface listed rooms, joined a match, left, created a demo room, and rendered live ping samples in a headless browser with no page errors.

### Cross-network connectivity

- GitHub Actions run [41797208954](https://github.com/dixonSolutions/LiveEngine/actions/runs/41797208954) succeeded.
- A GitHub-hosted runner connected over HTTPS to the local service through a temporary Cloudflare tunnel.
- The runner created a hub/room/player, paired the player, and deleted the test hub.
- The tunnel was stopped and its temporary repository secret removed after the check.

### Gogh Strike

- Cloned upstream, applied the optional hub matchmaking lobby, passed its 168 upstream tests and build.
- A real central-to-remote join and headless browser play flow passed without page errors, including plain-HTTP LAN hosting where `crypto.randomUUID` is unavailable.
- The game remains locally simulated; this check does not claim multiplayer game-state replication.

## Not verified

- Other devices on the maintainer's Tailscale network were offline during inspection.
- A physical tablet or phone test has **not** been performed.
- The successful external runner proves connectivity from a separate network; it does not prove a specific device or client works.
- The Gogh Strike test ran against local central and remote HTTP services, not a remote physical device.
- Registry publication/trust state is account-side; this page does not independently verify current registry credentials.

## How to reproduce

```sh
cargo fmt --all -- --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
npm ci
npm test
npm run test:integration
npm run build:hub
npm pack --dry-run
cargo package --locked
```

Containers:

```sh
docker build -t liveengine:test .
docker build -f Dockerfile.custom -t liveengine-custom:test .
bash scripts/test-containers.sh docker liveengine:test liveengine-custom:test
```

Cross-network:

```sh
LIVEENGINE_NETWORK_URL=https://your-hub.example \
LIVEENGINE_NETWORK_TEST_TOKEN="$LIVEENGINE_TOKEN" \
node scripts/test-network.js
```

See [Cross-network testing](/guides/network-testing) and [Contributing](/contributing).
