All DTOs use camelCase. Registration, call, and import bodies reject unknown fields.

## HubRegistration

```ts
interface HubRegistration {
  id: string;
  mode?: 'internal' | 'external' | 'central'; // required unless a template supplies it
  address?: string;
  remoteHubId?: string;
  remoteToken?: string;
  scopes?: object;       // default {}
  scopeSchema?: object;
  ttlSeconds?: number;
  schemaRef?: string;
  userSchema?: object | boolean;
  serverSchema?: object | boolean;
  template?: string;
  ifAbsent?: boolean;
  maxHubs?: number;
}
```

### Internal example

```json
{
  "id": "ranked-au",
  "mode": "internal",
  "scopes": {
    "game": "chess",
    "region": "au"
  },
  "scopeSchema": {
    "type": "object",
    "required": ["region"],
    "properties": {
      "region": { "type": "string", "enum": ["au", "nz"] }
    },
    "additionalProperties": false
  },
  "ttlSeconds": 3600
}
```

Internal registrations must **not** contain `address`, `remoteHubId`, or `remoteToken`. Supplying any of them returns `400`.

### External example

```json
{
  "id": "remote-ranked",
  "mode": "external",
  "address": "https://remote.example.net",
  "remoteHubId": "ranked-au",
  "remoteToken": "a-separate-remote-secret-at-least-24-bytes",
  "scopes": {
    "region": "au"
  },
  "ttlSeconds": 3600
}
```

External requirements:

| Field | Requirement |
| --- | --- |
| `address` | Required; absolute HTTP(S), no credentials/query/fragment, at most 2048 bytes |
| `remoteToken` | Required; at least 24 bytes |
| `remoteHubId` | Optional; defaults to `id`; same ID rules |
| Remote host | Must match `LIVEENGINE_ALLOWED_REMOTE_HOSTS` before connection |

## Field rules

| Field | Rules |
| --- | --- |
| `id` | 1–128 chars of `A-Z a-z 0-9 . _ -`; not `.` or `..`; no surrounding whitespace |
| `mode` | `internal`, `external`, or `central` |
| `scopes` | Must be a JSON object; must fit `max_request_bytes`; validated by `scopeSchema` when present |
| `scopeSchema` | JSON Schema 2020-12; see below |
| `ttlSeconds` | Integer at least 1; at most `max_ttl` (default 86400) |

`remoteToken` is write-only and is omitted from every response.

## HubInfo

```ts
interface HubInfo {
  id: string;
  mode: 'internal' | 'external' | 'central';
  address?: string;
  remoteHubId: string;
  scopes: object;
  scopeSchema?: object;
  expiresInSeconds?: number;
}
```

`expiresInSeconds` is recomputed when the record is read. It is omitted for permanent registrations. `remoteToken` never appears.

## Discovery

`GET /v1/hubs`:

```json
{
  "hubs": [
    {
      "id": "ranked-au",
      "mode": "internal",
      "remoteHubId": "ranked-au",
      "scopes": { "region": "au" },
      "expiresInSeconds": 3540
    }
  ]
}
```

`GET /v1/hubs/{id}` returns a single `HubInfo` object rather than a wrapper.

## CallRequest

```ts
interface CallRequest {
  method: string;    // 1–128 bytes
  args?: unknown[];  // default []
}
```

```json
{
  "method": "upsertUsers",
  "args": [
    [
      { "id": "alice", "scopes": { "region": "au" } },
      { "id": "bob", "scopes": { "region": "au" } }
    ]
  ]
}
```

Method arguments follow the engine method signatures. Custom handlers may accept arbitrary JSON.

## CallResponse

```ts
interface CallResponse {
  result: unknown;
}
```

```json
{ "result": true }
```

```json
{ "result": { "ok": true, "reason": null, "userId": "alice", "serverId": "room-1" } }
```

Application failures are still `200`; inspect `result.ok` and `result.reason`.

## RegistryImport

```ts
interface RegistryImport {
  address: string;
  token: string;    // at least 24 bytes
  prefix?: string;  // at most 64 chars of A-Z a-z 0-9 . _ -
  refreshSeconds?: number; // 1–86400
}
```

```json
{
  "address": "https://remote.example.net",
  "token": "a-remote-administrative-token",
  "prefix": "partner-"
}
```

Response:

```json
{
  "hubs": [
    {
      "id": "partner-ranked-au",
      "mode": "external",
      "address": "https://remote.example.net",
      "remoteHubId": "ranked-au",
      "scopes": { "region": "au" }
    }
  ]
}
```

## Error

```ts
interface ErrorResponse {
  error: string;
}
```

```json
{ "error": "hub id already registered" }
```

## Schemas and forwarding

Schemas use JSON Schema 2020-12. Only local JSON pointer references are supported; remote references, IDs, anchors and cycles are rejected. A hub accepts `scopeSchema` or `schemaRef`, with optional `userSchema` and `serverSchema`; inherited schemas apply to nested children. Schema-bound hubs reject `generateUsers`.

Forwarding uses `x-liveengine-trace` and `x-liveengine-depth`. Repeated instance IDs and depth exhaustion return 508. `LIVEENGINE_MAX_DEPTH` defaults to 8 and is capped at 16. Clients should not set forwarding headers. Registry definitions can be persisted using `LIVEENGINE_STATE_FILE`; live rooms and players remain in memory. See [nesting](/guides/nesting) and [schemas](/guides/schemas).
