---
title: "HTTP endpoints"
description: "Method, authentication, body, response, and status codes for every liveengine.hub/v1 route."
---

All examples assume:

```sh
export HUB=http://127.0.0.1:8787
export TOKEN="$LIVEENGINE_TOKEN"
```

HTTP routes except `/health` and `/v1/ping` require:

```http
Authorization: Bearer <token>
```

Request bodies use `application/json`. Error responses use `{"error":"..."}`.

## GET /health

Unauthenticated liveness check. It does not consume a rate slot.

```sh
curl --fail --silent "$HUB/health"
```

```json
{
  "status": "ok",
  "protocol": "liveengine.hub/v1",
  "uptimeSeconds": 42
}
```

| Status | Meaning |
| --- | --- |
| `200` | Running |

## GET /v1/ping

Unauthenticated latency probe. It does not consume a rate slot or expose state.

```sh
curl --fail --silent "$HUB/v1/ping"
```

```json
{
  "protocol": "liveengine.hub/v1",
  "pong": true,
  "serverTimeMs": 1793782157480,
  "processingMicros": 0,
  "uptimeSeconds": 42
}
```

| Field | Meaning |
| --- | --- |
| `protocol` | Protocol version |
| `pong` | Always `true` on success |
| `serverTimeMs` | Server wall clock in Unix milliseconds |
| `processingMicros` | Native handler time before serialization |
| `uptimeSeconds` | Host uptime |

| Status | Meaning |
| --- | --- |
| `200` | Pong |

## GET /v1/contract

Capability handshake. The router also exposes discovery, pairing, room WebSockets and individual link routes; see the full route table below.

```sh
curl --silent -H "Authorization: Bearer $TOKEN" "$HUB/v1/contract"
```

```json
{
  "protocol": "liveengine.hub/v1",
  "version": 1,
  "endpoints": [
    "/health", "/v1/ping", "/v1/contract", "/v1/hubs", "/v1/hubs/{id}",
    "/v1/hubs/{id}/call", "/v1/hubs/{id}/tickets", "/v1/hubs/{id}/link-credentials",
    "/v1/tickets/watch", "/v1/live/registry", "/v1/links", "/v1/registries/import",
    "/v1/registry/export", "/v1/schemas", "/v1/schemas/{id}", "/v1/templates",
    "/v1/templates/{name}", "/v1/route", "/v1/tree"
  ],
  "schema": "/v1/contract/schema"
}
```

| Status | Meaning |
| --- | --- |
| `200` | Contract |
| `401` | Missing or invalid token |
| `429` | Peer rate budget exhausted |
| `504` | Request timeout |

## GET /v1/hubs

Lists public metadata for live registrations, sorted by hub ID.

```sh
curl --silent -H "Authorization: Bearer $TOKEN" "$HUB/v1/hubs"
```

```json
{
  "hubs": [
    {
      "id": "ranked-au",
      "mode": "internal",
      "remoteHubId": "ranked-au",
      "scopes": { "game": "chess", "region": "au" },
      "scopeSchema": {
        "type": "object",
        "required": ["region"],
        "properties": { "region": { "type": "string" } }
      },
      "expiresInSeconds": 3540
    },
    {
      "id": "remote-ranked",
      "mode": "external",
      "address": "https://remote.example.net",
      "remoteHubId": "ranked-au",
      "scopes": { "game": "chess" }
    }
  ]
}
```

`address` and `scopeSchema` are omitted when absent. `expiresInSeconds` is omitted for permanent registrations. `remoteToken` is never returned.

| Status | Meaning |
| --- | --- |
| `200` | Hub list |
| `401` / `429` / `504` | Auth, rate, timeout |

## POST /v1/hubs

Registers an internal or external hub.

```sh
curl --silent -X POST \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "id": "ranked-au",
    "mode": "internal",
    "scopes": { "game": "chess", "region": "au" }
  }' \
  "$HUB/v1/hubs"
```

```json
{
  "id": "ranked-au",
  "mode": "internal",
  "remoteHubId": "ranked-au",
  "scopes": { "game": "chess", "region": "au" }
}
```

Returns `201 Created` with public `HubInfo`.

| Status | Meaning |
| --- | --- |
| `201` | Registered |
| `400` | Invalid DTO, ID, scopes, schema, TTL, address, or disallowed remote host |
| `401` | Unauthorized |
| `409` | Hub ID already registered |
| `429` | Rate limit |
| `502` | External handshake failed |
| `504` | Request timeout |
| `507` | Registry is full |

An internal registration creates a new engine. An external registration performs health, contract, and remote-hub presence checks before it is stored. See [Registration DTOs](/protocol/registration).

## DELETE /v1/hubs/{id}

Removes a registration.

```sh
curl --silent -X DELETE -H "Authorization: Bearer $TOKEN" "$HUB/v1/hubs/ranked-au"
```

| Status | Meaning |
| --- | --- |
| `204` | Removed; no body |
| `401` | Unauthorized |
| `404` | Hub not found |
| `429` | Rate limit |
| `504` | Request timeout |

Deleting an external registration does not stop or delete the remote hub. It detaches the local route only.

## POST /v1/hubs/{id}/call

Invokes a method on a hub.

```sh
curl --silent -X POST \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "method": "autoJoin", "args": ["alice"] }' \
  "$HUB/v1/hubs/ranked-au/call"
```

```json
{
  "result": {
    "ok": true,
    "reason": null,
    "userId": "alice",
    "serverId": "room-1"
  }
}
```

Request:

```ts
interface CallRequest {
  method: string;      // 1–128 bytes
  args?: unknown[];    // default []
}
```

The host checks, in order:

1. JSON body parses and uses known fields.
2. `method` is 1–128 bytes.
3. Serialized call size is within `max_request_bytes`.
4. `args.length <= max_args`.
5. `generateUsers` count is within `max_generates_per_call`.
6. Argument nesting depth is at most 64.
7. The hub exists.
8. If the hub has `scopeSchema`, upsert scopes are valid and `generateUsers` is rejected.
9. An in-flight slot is available.
10. The forwarding trace and depth are valid and within the configured limit.
11. The internal handler or remote call runs.
12. The result is within response size, entity, and event limits.

| Status | Meaning |
| --- | --- |
| `200` | Method returned; `result` may itself describe an application failure |
| `400` | Invalid call, invalid method, deep nesting, schema violation, handler error, invalid hop |
| `401` | Unauthorized |
| `404` | Hub not found or expired |
| `409` | Internal handler is busy |
| `413` | Request/response size, argument count, generate count, or entity/event budget exceeded |
| `429` | Rate limit |
| `500` | Handler task failed |
| `502` | Remote request/handshake/JSON failure |
| `503` | In-flight capacity busy or handler unavailable |
| `504` | Request timeout |
| `508` | Forwarding depth or loop detected |

An application failure is a `200` with a result such as:

```json
{
  "result": {
    "ok": false,
    "reason": "no_fit",
    "userId": "alice",
    "serverId": null
  }
}
```

## POST /v1/registries/import

Imports a snapshot of another registry.

```sh
curl --silent -X POST \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "address": "https://remote.example.net",
    "token": "'"$REMOTE_TOKEN"'",
    "prefix": "partner-"
  }' \
  "$HUB/v1/registries/import"
```

```json
{
  "hubs": [
    {
      "id": "partner-ranked-au",
      "mode": "external",
      "address": "https://remote.example.net",
      "remoteHubId": "ranked-au",
      "scopes": { "game": "chess" }
    }
  ]
}
```

| Status | Meaning |
| --- | --- |
| `200` | Imported or already attached |
| `400` | Invalid body, token, prefix, address, or disallowed host |
| `401` | Unauthorized |
| `409` | ID mapped to a different target, or concurrent registration |
| `413` | Remote hub list exceeds `max_hubs` |
| `429` | Rate limit |
| `502` | Remote health/contract/list/handshake failure, malformed registry, duplicate remote IDs |
| `504` | Request timeout |
| `507` | Local registry would exceed `max_hubs` |

Set `refreshSeconds` to periodically refresh; missing entries are marked stale.

## Common statuses

| Status | Name | Typical cause |
| --- | --- | --- |
| `400` | Bad Request | Invalid DTO, ID, scopes, address, prefix, method, or hop |
| `401` | Unauthorized | Missing or wrong bearer token |
| `403` | Forbidden | User not paired in the room, `credential refused` by hub `auth`, or a provider credential outside its scope |
| `404` | Not Found | Unknown route or hub |
| `408` | Request Timeout | A waiting `pair` ended with no partner |
| `409` | Conflict | Duplicate ID, busy handler, import mapping conflict |
| `413` | Payload Too Large | Body/response size, args, generate count, entity/event budget |
| `429` | Too Many Requests | Peer rate budget exhausted |
| `500` | Internal Server Error | Handler task failure or schema load failure |
| `502` | Bad Gateway | Remote handshake, request, JSON, or registry failure |
| `503` | Service Unavailable | In-flight capacity or unavailable handler |
| `504` | Gateway Timeout | Request exceeded `request_timeout` |
| `507` | Insufficient Storage | Hub registry is full |
| `508` | Loop Detected | Forwarding depth or loop detected |

## Nested routing, schemas, templates and export

All routes below require the admin bearer token.

| Method | Route | Purpose |
| --- | --- | --- |
| POST | `/v1/route` | `{path, op, body}`; op is `get`, `list`, `register`, `delete`, `call`, `tree`, `ticket`, `watchTicket`, `authorize`, `discover`, or `pair` |
| GET | `/v1/tree?depth=2` | Bounded recursive discovery with per-branch status |
| GET, POST | `/v1/schemas` | List or create immutable `{id, version, schema}` definitions |
| GET, DELETE | `/v1/schemas/{id@version}` | Read or delete a schema; in-use deletion returns 409 |
| GET, POST | `/v1/templates` | List or create templates |
| GET, DELETE | `/v1/templates/{name}` | Read or delete a template |
| GET | `/v1/registry/export` | Export hub and schema definitions without credentials |

For route `get`, `delete` and `call`, provide `body.id`; calls also require `method` and optional `args`. A path selects central namespaces, and an empty path targets the root. A registration accepts `template`, `ifAbsent`, `schemaRef`, `userSchema`, `serverSchema`, and `maxHubs`. Registry import accepts `refreshSeconds`. See [nesting](/guides/nesting) and [schemas](/guides/schemas).

## Live, pairing and links

| Method | Route | Purpose |
| --- | --- | --- |
| POST | `/v1/discover` | Find matching hubs and peers |
| POST | `/v1/pair` | Pair a subject and return a connection descriptor; optional `waitMs` |
| POST | `/v1/hubs/{id}/tickets` | Issue a single-use room ticket to a paired participant |
| POST | `/v1/tickets/watch` | Issue a path- and depth-scoped registry watch ticket |
| GET (WebSocket) | `/v1/live` | Authenticate in the first frame with a room ticket |
| GET (WebSocket) | `/v1/live/registry` | Authenticate in the first frame with an admin token or watch ticket |
| GET, POST, DELETE | `/v1/links` | List, create, or delete by `?id=` |
| GET, DELETE | `/v1/links/{id}` | Inspect or delete a link |
| POST, DELETE | `/v1/hubs/{id}/link-credentials` | Issue a link token once or revoke all link tokens for the hub |

WebSocket browser origins must be allowed. Link tokens can request only service-role tickets on their own hub. See [live rooms](/guides/live-rooms) and [hub links](/guides/hub-links).
