## Dependency

```toml
[dependencies]
liveengine = "0.5"
serde_json = "1"
```

Rust 1.88 or newer is required. The crate exports:

```rust fragment
pub mod engine;
#[cfg(feature = "host")] pub mod hub;
pub mod rules;
pub use engine::Engine;
pub const VERSION: &str = env!("CARGO_PKG_VERSION");
```

## Feature flags

| Feature | Default | Enables |
| --- | --- | --- |
| `host` | yes | `hub` module, Axum, Tokio, reqwest, URL, futures, subtle, tower; the `liveengine-hub` binary |
| `node` | no | N-API bindings used by the npm package |

Engine-only dependency:

```toml
[dependencies]
liveengine = { version = "0.5", default-features = false }
```

With `default-features = false`, only `Engine`, `rules`, and `VERSION` are available. There is no Node or hosting dependency.

## Engine

```rust fragment
pub struct Engine { /* private */ }

impl Engine {
    pub fn new(seed: u64) -> Self;
    pub fn dispatch(&mut self, method: &str, args: Vec<serde_json::Value>)
        -> Result<serde_json::Value, String>;
    // ...and one typed method per dispatch method, listed below.
}
pub const DISPATCH_METHODS: &[&str];
```

Every `dispatch` method also has a typed method named like it in snake case (`upsertUser` is `upsert_user`). Each is a thin wrapper over `dispatch`, with the same validation, errors and events, so you can mix the two. Users, servers, options and results are your own JSON shapes and stay `serde_json::Value`; counts are `usize`, flags `bool`, lookups `Option<Value>` and lists `Vec<Value>`. `liveengine::engine::DISPATCH_METHODS` lists every method name, and a test keeps it, `dispatch` and the typed methods in step.

```rust
use liveengine::Engine;
use serde_json::json;

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let mut engine = Engine::new(42);

    let added = engine.dispatch(
        "upsertServer",
        vec![json!({
            "id": "room-au",
            "capacity": 2,
            "minMembers": 2,
            "scopes": { "game": "chess", "region": "au" },
            "requirements": { "rating": { "between": [1300, 1700] } }
        })],
    )?;
    assert_eq!(added, json!(true));

    engine.dispatch(
        "upsertUser",
        vec![json!({
            "id": "alice",
            "scopes": { "game": "chess", "region": "au", "rating": 1450 },
            "requirements": { "game": "chess", "region": "au" }
        })],
    )?;

    let result = engine.dispatch("autoJoin", vec![json!("alice")])?;
    println!("{result}");
    Ok(())
}
```

`dispatch` returns `Ok(Value)` for a successful method call, including application-level failures such as `{ "ok": false, "reason": "no_fit" }`. It returns `Err(String)` for malformed input, unknown methods, invalid requirements, invalid generators, and invalid statuses.

## Methods

The method names, argument order, and result shapes match the [Node engine reference](/node/engine). Every Node method maps directly to `dispatch` and to a typed method:

| `dispatch` method | Arguments | Typed method |
| --- | --- | --- |
| `upsertUser` | `user` | `upsert_user(Value) -> Result<bool, String>` (true when added) |
| `upsertUsers` | `[users]` | `upsert_users(Vec<Value>) -> Result<usize, String>` |
| `removeUser` | `id` | `remove_user(&str) -> Result<bool, String>` |
| `getUser` | `id` | `get_user(&str) -> Result<Option<Value>, String>` |
| `listUsers` | optional `status` | `list_users(Option<&str>) -> Result<Vec<Value>, String>` |
| `setUserStatus` | `id`, `status` | `set_user_status(&str, &str) -> Result<bool, String>` |
| `upsertServer` | `server` | `upsert_server(Value) -> Result<bool, String>` |
| `upsertServers` | `[servers]` | `upsert_servers(Vec<Value>) -> Result<usize, String>` |
| `removeServer` | `id` | `remove_server(&str) -> Result<bool, String>` |
| `getServer` | `id` | `get_server(&str) -> Result<Option<Value>, String>` |
| `listServers` | optional `status` | `list_servers(Option<&str>) -> Result<Vec<Value>, String>` |
| `setServerStatus` | `id`, `status` | `set_server_status(&str, &str) -> Result<bool, String>` |
| `findServersForUser` | `userId`, optional options | `find_servers_for_user(&str, Option<Value>) -> Result<Vec<Value>, String>` |
| `findUsersForServer` | `serverId`, optional options | `find_users_for_server(&str, Option<Value>) -> Result<Vec<Value>, String>` |
| `fits` | `userId`, `serverId` | `fits(&str, &str) -> Result<bool, String>` |
| `advertise` | `userId`, optional options | `advertise(&str, Option<Value>) -> Result<usize, String>` |
| `advertiseAll` | optional options | `advertise_all(Option<Value>) -> Result<usize, String>` |
| `join` | `userId`, `serverId` | `join(&str, &str) -> Result<Value, String>` |
| `leave` | `userId` | `leave(&str) -> Result<Value, String>` |
| `autoJoin` | `userId`, optional options | `auto_join(&str, Option<Value>) -> Result<Value, String>` |
| `matchAll` | optional options | `match_all(Option<Value>) -> Result<Vec<Value>, String>` |
| `generateUsers` | `count`, optional spec | `generate_users(usize, Option<Value>) -> Result<Vec<Value>, String>` |
| `drainEvents` | none | `drain_events() -> Result<Vec<Value>, String>` |
| `pendingEvents` | none | `pending_events() -> Result<usize, String>` |
| `stats` | none | `stats() -> Result<Value, String>` |
| `clear` | none | `clear() -> Result<(), String>` |
| `reseed` | `seed` | `reseed(u64) -> Result<(), String>` |
| `pairPeers` | `{room, capacity, users}` | `pair_peers(Value) -> Result<Value, String>`; hub pairing uses it |

Every typed method takes `&mut self`, like `dispatch`.

```rust
use liveengine::Engine;
use serde_json::json;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let mut engine = Engine::new(42);
    engine.upsert_server(json!({ "id": "room-au", "capacity": 2, "scopes": { "region": "au" } }))?;
    engine.upsert_users(vec![
        json!({ "id": "alice", "requirements": { "region": "au" } }),
        json!({ "id": "bob", "requirements": { "region": "au" } }),
    ])?;
    assert!(engine.fits("alice", "room-au")?);
    for seat in engine.match_all(None)? {
        println!("{} -> {}", seat["userId"], seat["serverId"]);
    }
    let alice = engine.get_user("alice")?.expect("alice exists");
    println!("{}", alice["status"]);
    println!("{} events", engine.drain_events()?.len());
    Ok(())
}
```

The same calls through `dispatch`:

```rust
use liveengine::Engine;
use serde_json::json;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let mut engine = Engine::new(42);
    let stats = engine.dispatch("stats", vec![])?;
    let events = engine.dispatch("drainEvents", vec![])?;
    let pending = engine.dispatch("pendingEvents", vec![])?;
    engine.dispatch("reseed", vec![json!(99)])?;
    Ok(())
}
```

## Rules module

`rules` exposes the requirement parser and evaluator directly:

```rust
use liveengine::rules;

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    use serde_json::json;
    let requirements = rules::parse_requirements(Some(&json!({
        "region": ["au", "nz"],
        "rating": { "between": [1200, 1800] }
    })))?;

    let scopes = json!({ "region": "au", "rating": 1500 });
    assert!(rules::evaluate(&requirements, &scopes));
    Ok(())
}
```

- `parse_requirements(Option<&Value>) -> Result<Value, String>` normalizes shorthand, arrays, and rule sets.
- `scopes(Option<&Value>) -> Value` normalizes a scope map (arrays become string arrays).
- `evaluate(&Value, &Value) -> bool` applies the rule set to scopes.

The internal representation is `{ "rules": [...], "match": "all" | "any" }`. See [Requirements](/concepts/requirements).

## Determinism and generation

The engine uses a seeded ChaCha8 RNG. `Engine::new(seed)` and `reseed(seed)` control generated users and the `random` strategy. Generation specs follow the same schema as Node:

```rust
use liveengine::Engine;
use serde_json::json;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let mut engine = Engine::new(42);
    let users = engine.dispatch(
        "generateUsers",
        vec![
            json!(100),
            json!({
                "idPrefix": "bot-",
                "scopes": {
                    "rating": { "type": "int", "min": 1000, "max": 2000 },
                    "region": ["eu", "us", "apac"],
                    "tags": { "type": "tags", "values": ["a", "b", "c"], "count": 2 }
                },
                "requirements": { "game": "chess" }
            }),
        ],
    )?;
    Ok(())
}
```

Generation validates every generator before inserting users. Invalid ranges, probabilities, empty pools, unknown types, or output above 64 MiB return `Err` without partial mutation.

## Errors

```rust
use liveengine::Engine;
use serde_json::json;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let mut engine = Engine::new(42);
    match engine.dispatch("join", vec![json!("alice"), json!("room")]) {
        Ok(result) => {
            if result["ok"] == false {
                eprintln!("application result: {}", result["reason"]);
            }
        }
        Err(message) => eprintln!("invalid call: {message}"),
    }
    Ok(())
}
```

Error strings are stable enough for diagnostics but are not a typed error enum. Do not branch on exact message text in production; branch on the structured `ok`/`reason` fields for application results.

## Threading

`Engine` is `Send` and uses `&mut self` for every operation. It is not internally synchronized. Wrap it in your own `Mutex` if multiple tasks need access. The hosted `HubService` already wraps each engine in a mutex and runs calls on blocking workers.
